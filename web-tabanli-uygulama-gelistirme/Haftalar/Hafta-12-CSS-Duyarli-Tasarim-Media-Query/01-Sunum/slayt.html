Duyarlı (Responsive)
Tasarım ve Media Query

Aynı sayfanın, telefonda da masaüstünde de düzgün görünmesini nasıl sağlarız?

01 — Sorunun Kaynağı

Tek Sayfa, Sonsuz Ekran Boyutu

  • Bir web sayfası; 6 inçlik telefonda, 10 inçlik tablette, 15 inçlik dizüstünde ve 27 inçlik masaüstü monitörde aynı anda açılabilir.
  • Duyarlı (responsive) tasarım, sayfanın bu farklı ekran genişliklerine göre kendini otomatik olarak uyarlamasıdır.
  • Günümüzde internet trafiğinin yarısından fazlası mobil cihazlardan gelir — "önce masaüstü, mobili sonra düşünürüz" yaklaşımı artık kabul edilebilir değildir.
02 — Canlı Kanıt — Sabit Genişlik Sorunu

Sabit Piksel mi, Esnek Birim mi?

width: 900px (SABİT)

Dar Ekranda Taşıyor

telefon görünümü
max-width: 900px; width: 100%

Her Ekrana Uyum Sağlıyor

telefon görünümü
Bu, ödevde ve örnek uygulamada canlı olarak tekrar göreceğimiz "mobilde neden bozuk görünüyor" hatasının temel nedenlerinden biridir.
03 — Hatırlatma

<meta name="viewport"> Olmadan Olmaz

  • Hafta 3'te gördüğümüz bu satırı hatırlayın — duyarlı tasarımın ön koşuludur.
  • Bu satır eksikse, mobil tarayıcılar sayfayı "masaüstü boyutunda" varsayıp otomatik olarak küçültür — kullanıcı yazıları okumak için parmaklarıyla yakınlaştırmak zorunda kalır.
  • Bu satır varsa, sayfa gerçek ekran genişliğinde (device-width) render edilir ve yazdığımız duyarlı kurallar devreye girer.
Kod
<meta name="viewport"
  content="width=device-width, initial-scale=1.0">
04 — Yeni Araç

Media Query Nedir?

  • Media query, "ekran şu koşulu sağlıyorsa bu CSS kurallarını uygula" diyen özel bir CSS bloğudur.
  • @media ile başlar, parantez içinde bir koşul (örn. ekran genişliği), süslü parantez içinde de normal CSS kuralları yazılır.
  • Bir sayfada istediğiniz kadar media query bloğu olabilir.
Kod
.menu { display: flex; }

@media (max-width: 768px) {
  .menu { flex-direction: column; }
}
Yukarıdaki örnek: ekran 768px'den dar olduğunda, menü öğelerini yan yana değil alt alta dizer.
05 — En Sık Yapılan Hata

max-width mi, min-width mi?

max-width: 768px

"Ekran en fazla 768px ise" — yani 768px ve daha dar ekranlarda uygulanır. Genelde "mobilde şunu değiştir" demek için kullanılır.

min-width: 768px

"Ekran en az 768px ise" — yani 768px ve daha geniş ekranlarda uygulanır. Genelde "masaüstünde şunu ekle" demek için kullanılır.

Bu ikisini karıştırmak (örn. mobil stilini min-width ile yazmak), kuralın tam tersi ekranda uygulanmasına yol açar — birazdan örnek uygulamada tam olarak bu hatayı avlayacağız.
06 — Strateji Seçimi

Mobile-First mi, Desktop-First mi?

GÜNCEL YAKLAŞIM

Mobile-First

Önce mobil için temel stiller yazılır, sonra min-width ile büyük ekranlara ekleme yapılır. Daha az kod, daha performanslı — çünkü mobil zaten "varsayılan" durumdur.

Desktop-First

Önce masaüstü için tam stiller yazılır, sonra max-width ile küçük ekranlarda geçersiz kılınır (override). Eski/klasik yaklaşım, öğrenmesi bu derste daha kolay olduğu için biz bunu kullanacağız.

İkisi de doğrudur, önemli olan tutarlı seçmektir. Bu ders boyunca örneklerimizde desktop-first (max-width) yaklaşımını kullanacağız.
07 — Yaygın Değerler

Breakpoint (Kırılma Noktası)

  • Breakpoint, tasarımın "kırılıp" farklı bir düzene geçtiği ekran genişliğidir.
  • Kesin bir kural yoktur, ama yaygın kullanılan yaklaşık değerler:
Telefon: ~480px Tablet: ~768px Küçük Dizüstü: ~1024px Masaüstü: 1200px+
En sağlıklı yöntem: cihaz listesinden ezbere değer almak değil, kendi tasarımınızı tarayıcı penceresini yavaşça daraltarak nerede "bozulmaya başladığını" gözlemleyip breakpoint'i oradan seçmektir.
08 — Akıcı Boyutlandırma

clamp() ile Esnek Yazı Boyutu

MEDIA QUERY İLE

Aşamalı, Sıçramalı

h1 { font-size: 22px; }
@media (min-width:768px){
  h1{font-size:32px;}
}
@media (min-width:1200px){
  h1{font-size:48px;}
}
clamp() İLE

Tek Satır, Pürüzsüz Geçiş

h1 {
  font-size: clamp(22px, 4vw, 48px);
}
// min: 22px, tercih: ekranın %4'ü, max: 48px
clamp(min, tercih, max) — üç değer arasında tarayıcı otomatik, akıcı bir geçiş yapar; her ekran genişliği için ayrı satır yazmaya gerek kalmaz.
09 — Görsellerde Duyarlılık

Resimler Taşmasın

  • Bir <img> etiketine genişlik verilmezse, resmin orijinal boyutu kullanılır — konteynerinden taşabilir.
  • Standart çözüm: her görsele bu iki kuralı uygulamak.
  • height: auto, resmin en-boy oranını koruyarak deforme olmasını engeller.
Kod
img {
  max-width: 100%;
  height: auto;
}
10 — Güncel Not

Container Query — Bileşenin Kendi Genişliğine Göre

  • @media, tüm ekranın genişliğine bakar.
  • @container (2023 sonrası tüm modern tarayıcılarda desteklenir), bir bileşenin kendi konteynerinin genişliğine bakar — aynı kart bileşeni, geniş bir sayfada 3 sütunlu bir alanda farklı, dar bir kenar çubuğunda farklı görünebilir.
  • Bu ders kapsamında sadece farkındalık için tanıtılır, ileri seviye bir konudur.
11 — Test Etme

Chrome DevTools — Cihaz Araç Çubuğu

  • Gerçek bir telefon olmadan, sayfamızın mobilde nasıl göründüğünü test edebiliriz.
  • F12 ile geliştirici araçlarını açın, sonra sol üstteki telefon/tablet simgesine tıklayın (kısayol: Ctrl+Shift+M).
  • Üstteki menüden farklı cihaz modelleri (iPhone, Galaxy, iPad) seçilebilir, veya genişlik elle sürüklenebilir.
Bu araç, birazdan yapacağımız "mobilde neden bozuk görünüyor" uygulamasında sürekli kullanılacak — şimdiden açıp deneyin.
12 — Gerçek Proje

"Okulum" — Mobilde Dikey Menü

  • Şimdiye kadar yan yana duran üst menümüzü (nav), dar ekranlarda alt alta dizeceğiz.
  • Ayrıca başlık yazı boyutunu clamp() ile akıcı hale getireceğiz.
.site-nav { display: flex; gap: 20px; }

@media (max-width: 700px) {
  .site-nav { flex-direction: column; gap: 8px; }
}

h1 { font-size: clamp(24px, 5vw, 44px); }
