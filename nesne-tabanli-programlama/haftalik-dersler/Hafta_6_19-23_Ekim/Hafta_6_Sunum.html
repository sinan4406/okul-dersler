&& yalnızca hepsi doğruysa doğrudur.

Günlük dil: “Kimlik ve bilet varsa girebilirsin.” · “Nakit veya kartla ödeyebilirsin.”

Etkinlik: Çalışma kâğıdındaki boş tabloyu slaytı kapatarak doldurun.

Önce tabloyu kapalı tutup öğrencilere boş tabloyu doldurtun (çalışma kâğıdı). Sonra bu slaytı açıp karşılaştırın. Kırmızı hücreler false sonuçlarıdır. Dikkat: Günlük dildeki “veya” bazen “ikisinden yalnız biri” anlamına gelir (çay veya kahve). C#’taki || ise ikisi de doğruysa da true verir. Bu fark sık karışır.

3. saat · Operatör önceliği

&& her zaman || ’den önce işlenir

Yukarıdan aşağı: önce işlenen

2* / % → + -

4&&

true || false && false

true || (false && false) → true || false → true

Örnek: Dosya türü testi (kitaptaki 16. uygulamanın tamamı)

Formda uzantı listesi (MP4, MOV, JPG, PNG) ve “Video” / “Resim” radyo düğmeleri var. Öğrenci uzantının türünü doğru işaretledi mi?

string secim = listBox1.SelectedItem.ToString(); // seçilen uzantı
bool videoDedi = radioButton1.Checked;           // "Video" işaretli mi?

// HATALI: && önce işlenir, MOV her zaman "Doğru" olur
if (videoDedi && secim == "MP4" || secim == "MOV")
    MessageBox.Show("Cevabınız Doğru");

// DOĞRU: VEYA kısmı parantez içinde
if (videoDedi && (secim == "MP4" || secim == "MOV"))
    MessageBox.Show("Cevabınız Doğru");
“Cevabınız Doğru” der, ama cevap yanlıştır. Bilgisayar şöyle okur: (videoDedi && secim == "MP4") || (secim == "MOV"). Sağ taraf tek başına true olduğu için radyo düğmesine hiç bakılmaz.
Önce hatalı kodu çalıştırtın: MOV seçip “Resim” işaretlesinler, “Cevabınız Doğru” mesajını görsünler. Sonra nedenini tahtada adım adım çözün. Etkinlik çıktısı: Her öğrenci “ne oldu, neden oldu, nasıl düzelttim” şeklinde 3 cümlelik bir hata raporu yazar. Altın kural: Öncelikten emin değilsen parantez kullan.

3. saat · Kitapta yok · Kısa devre değerlendirme

Cevap belli olunca C# gerisine bakmaz

A && B

A false ise sonuç kesin false. B hiç çalıştırılmaz.

A || B

A true ise sonuç kesin true. B hiç çalıştırılmaz.

Güvenli: önce kontrol, sonra işlem

int adet = 0, toplam = 0; // sepet boş
// 1) adet != 0 → false
// 2) && için sonuç belli: false
// 3) bölme hiç yapılmaz, çökme yok
if (adet != 0 && toplam / adet > 100)
    Yaz("Ortalama 100 TL üstü");

Çöker: sıra ters

int adet = 0, toplam = 0;
// 1) önce toplam / adet hesaplanır
// 2) 0 / 0 → DivideByZeroException
// 3) program burada durur
if (toplam / adet > 100 && adet != 0)
    Yaz("Ortalama 100 TL üstü");
Sıra yüzünden. Koruyucu koşul (adet != 0) solda olmalı. Sağdaki kodda bölme, kontrolden önce yapılıyor.
İki kodu da öğrencilere çalıştırtın: sağdaki kod uygulamayı çökertir. Aynı fikir null kontrolü için de geçerlidir: if (ad != null && ad.Length > 0). Ek bilgi: & ve | operatörleri kısa devre yapmaz, iki tarafı da her zaman çalıştırır; koşullarda neredeyse her zaman && ve || kullanılır. Performans notu: Pahalı kontrolü (örneğin veritabanı sorgusu) sağa, ucuz kontrolü sola yazmak programı hızlandırır.

2. saat · NOT ve De Morgan kuralları

! içeri girince && ile || yer değiştirir

!(A && B) = !A || !B

“Hem yağmurlu hem soğuk DEĞİL” = “ya yağmurlu değil ya da soğuk değil”

!(A || B) = !A && !B

“Nakit VEYA kart DEĞİL” = “nakit değil ve kart değil”

İfadeSadeleştirilmiş hali (eşinle bul, sonra aç)
!(yas >= 15 && yas <= 65) yas < 15 || yas > 65
!(stok >= 10) stok < 10
!(sayi > 0 && sayi < 10) sayi <= 0 || sayi >= 10
!(renk == "sarı") && no % 10 == 2 renk != "sarı" && no % 10 == 2

Karşılaştırma da tersine döner: >= olur <, < olur >=, == olur !=.

Son satırda dikkat: ! yalnızca hemen arkasındaki parantezi etkiler, çünkü önceliği en yüksektir. Bu yüzden && olduğu gibi kalır. Kodda neden işe yarar? Olumsuz koşullar beyni yorar; sadeleştirilmiş ifade daha hızlı okunur ve daha az hata yapılır.

Tahmin et → çalıştır → açıkla

Kodu çalıştırmadan sonucu yaz: true mu, false mu?

int yas = 17;     bool veliIzni = true;     double bakiye = 0;

1 yas >= 18 || veliIzni

true. 17 >= 18 false, ama veliIzni true. || için biri yeter.

2 yas >= 18 && veliIzni

false. 17 >= 18 false. && için tek false yeter; sağ tarafa bakılmaz.

3 !(yas < 18)

false. 17 < 18 true, ! ile tersine döner.

4 bakiye > 0 || yas > 16 && !veliIzni

false. Önce ! → !veliIzni = false. Sonra && → (true && false) = false. En son || → (false || false) = false.

Kitap s. 60, Tablo 2.4 · Kural: Sayaç ve biriktirici döngüden ÖNCE başlangıç değeri alır (genelde 0).

Kitaptaki x = x + 1 tablosunu gerçek senaryolarla zenginleştirdik. Sayaç ile biriktirici (accumulator) ayrımı kitapta yok ama döngü sorularının yarısı bu ikisinden birini ister. Bir de Not: int değişkende fiyat /= 2 ondalığı atar (15 / 2 = 7). Fiyat için decimal kullanılır.

5. saat · Kitapta yok · i++ ve ++i

İkisi de 1 artırır. Fark, değerin ne zaman okunduğunda

x++ · önce kullan, sonra artır

int x = 5;
int a = x++;  // 1) a'ya 5 verilir
               // 2) sonra x 6 olur
// sonuç: a = 5, x = 6

++x · önce artır, sonra kullan

int x = 5;
int b = ++x;  // 1) önce x 6 olur
               // 2) b'ye 6 verilir
// sonuç: b = 6, x = 6

Tahmin oyunu: x ve y kaç olur?

int x = 5;
int y = x++ + ++x;

x = 7, y = 12. x++ → 5 verir, x 6 olur. ++x → x 7 olur, 7 verir. 5 + 7 = 12.

Profesyonel kural

++ ve -- işlemini başka bir ifadenin içine gömme. Kendi satırında ya da for’un 3. kısmında kullan. for (…; …; i++) içinde i++ ile ++i arasında fark yoktur.

Öğrencilerin çoğu tahmin oyununda 11 veya 13 der. Bu, kuralın neden var olduğunu gösterir: okunması zor kod hataya açıktır ve kod incelemelerinde reddedilir.

Adım 1 / 1
Klavyedeki sağ ok tuşu da (ya da sunum kumandası) önce adımları ilerletir, adımlar bitince sonraki slayta geçer. Her adımda durup “Şimdi hangi parça çalışacak?” diye sorun. Tahmin et · 3 dakika · i’nin aldığı değerleri tek tek yaz


Her döngü kaç kez çalışır?






A  for (int i = 0; i < 10; i++)
10 kez: 0, 1, …, 9


B  for (int i = 1; i <= 10; i++)
10 kez: 1, 2, …, 10 (<= ile 10 dahil)


C  for (int i = 100; i <= 150; i += 5)
11 kez: 100, 105, …, 150


D  for (int i = 10; i > 0; i -= 3)
4 kez: 10, 7, 4, 1


E  for (int i = 1; i < 100; i *= 2)
7 kez: 1, 2, 4, 8, 16, 32, 64


F  for (int i = 0; i < 5; i--)
≈ 2,1 milyar kez! i hep azalır, program donar.






Kısa yol formülü: (bitiş − başlangıç) / adım + 1, ama yalnızca eşit adımlı ve bitişi tam yakalayan döngülerde. F seçeneği while bölümündeki sonsuz döngü konusuna köprüdür: int’in en küçük değeri −2.147.483.648’dir; daha da azaltılınca en büyük pozitif sayıya döner ve koşul false olur.

string sifre = txtSifre.Text;            // kutudaki şifre

// Her karakter türü için bir sayaç, hepsi 0'dan başlar
int rakam = 0, buyuk = 0, kucuk = 0, ozel = 0;

// i: ilk karakterden (0) son karaktere kadar her konum
for (int i = 0; i < sifre.Length; i++)
{
    char c = sifre[i];                   // i. karakteri al

    else if (char.IsLower(c)) kucuk++;   // a–z mi?
    else                      ozel++;    // geri kalan: ! ? * ...
}

1. adım: girdileri al, aylık taksiti hesapla








// 1) Formdaki kutulardan değerleri al
double anapara   = double.Parse(txtTutar.Text);        // örn. 10000
double aylikFaiz = double.Parse(txtFaiz.Text) / 100;  // %3 → 0,03
int    vade      = int.Parse(cmbVade.Text);            // örn. 3 ay

// 2) Faiz yoksa borç aylara eşit bölünür
double taksit = anapara / vade;

// 3) Faiz varsa bankaların eşit taksit formülü
if (aylikFaiz > 0)
{
    taksit = anapara * aylikFaiz
             / (1 - Math.Pow(1 + aylikFaiz, -vade));
}








Formül


taksit = P × r ÷ (1 − (1 + r)−n)


P: anapara · r: aylık faiz · n: vade (ay)






Örnek


10.000 TL, aylık %3, 3 ay



3.535,30 TL. 3 ayda toplam 10.605,91 TL ödenir.






Neden if?


Faiz 0 olursa formül 0 ÷ 0 olur (NaN). if bunu önler.








Formülü ezberletmeye gerek yok; amaç, programın kararı (faiz var mı?) if ile verdiğini görmek. Faizsiz taksit kampanyaları da bu yüzden ayrıca ele alınır. Gerçekte bankalar faize ayrıca BSMV ve KKDF vergisi ekler; ileri seviye öğrencilere ek görev olarak verilebilir.

2. adım: for ile her ayın satırını üret








double kalan = anapara;     // henüz ödenmemiş borç
double toplamFaiz = 0;      // biriktirici
lstPlan.Items.Clear();       // eski planı temizle

// Tur sayısı belli (vade kadar) → for
for (int ay = 1; ay <= vade; ay++)
{
    double faiz = kalan * aylikFaiz;     // bu ayın faizi
    double anaparaPayi = taksit - faiz;  // borçtan düşen kısım
    kalan -= anaparaPayi;                // borç azalır
    toplamFaiz += faiz;                  // faizleri biriktir

    lstPlan.Items.Add($"{ay}. ay  Faiz: {faiz:N2}  Kalan: {kalan:N2}");
}
lblOzet.Text = $"Toplam faiz: {toplamFaiz:N2} TL";

Kural sırası önemli: önce kritik, sonra uyarı kontrol edilir; kritik bir durumun “Uyarı” diye geçmesi engellenir. D3 biçimi okuma numarasını 3 haneye tamamlar (007), F1 bir ondalık gösterir. Meydan okuma: uyarı sayısını ve en yüksek sıcaklığı rapora eklemek.

// 18–65 yaş arası indirim
if (yas >= 18 || yas <= 65)
    indirim = 0.20m;


|| yerine &&. Her yaş ya ≥ 18 ya da ≤ 65’tir; koşul hep true.






3 · Geri sayım donuyor


// 10'dan 0'a geri say
for (int i = 10; i >= 0; i++)
    lstSayim.Items.Add(i);


i++ yerine i--. i büyüdükçe i >= 0 hep true kalır.

string ad = txtAd.Text;
if (ad[0] == 'A' && ad.Length > 0)
    Yaz("A ile başlıyor");


Sıra ters. Önce ad.Length > 0; boş metinde ad[0] çöker.
